FederatedLearning4Uformer

基于 Uformer 的联邦学习图像复原实现。 本页面汇总仓库 README 与源码中已记载的研究设定、训练流程与实验图示；无法在浏览器中运行或训练。

研究问题

本仓库将 Uformer（通用 U 型 Transformer 图像复原网络）扩展至联邦学习场景， 在数据分布于多个客户端、无法集中上传的前提下，通过服务端聚合实现协同训练。

基础模型

Uformer 面向图像去噪等低层视觉任务，采用局部增强窗口 Transformer 与跳跃连接设计。

来源：README.md 标题；model.py 文件头注释（引用 arXiv:2106.03106）

任务模式

默认配置为图像去噪（mode=denoising），数据集默认为 SIDD。

来源：options.py — dataset、mode 默认值

README 收敛描述

README 记载：拟合性能经验证，在通信次数约 1000 次范围内模型收敛至 SOTA 水平（原文表述，未给出具体数值指标）。

来源：README.md 第 12 行 — 作者自述，非独立基准测试报告
说明 本展示页不收录任何 README / 源码未记载的论文发表状态、对比实验表格或精确 SOTA 数值。 Uformer 原论文在 SIDD 上的 PSNR 等指标见 sr/README.md，与本仓库联邦实验为不同设定。

服务端—客户端流程

Server 下发全局参数 → 随机选取客户端（默认 4/16） → 各 Client 本地训练 → 上传参数 · 服务端取均值 → 验证集评估 · TensorBoard 记录
来源：server.py 通信循环与聚合逻辑；README.md 结构介绍

并行实现

  • 推荐版本：server.py（多线程），README 记载运行无问题。
  • server_Multiprocess.py：多进程实现，README 记载有概率死锁，不建议使用。
  • 聚合与评估在 cuda:0 上进行（README 记载不可更改设备）。
  • DataLoader 的 num_workers 必须为 0，否则可能死锁。
来源：README.md；options.py train_workers/eval_workers 默认 0

模型与训练管线

网络架构

arch=Uformer，embed_dim=32，win_size=8，train_ps=128。

来源：options.py

优化与损失

优化器 AdamW（lr=2e-4），损失函数 CharbonnierLoss，可选 warmup + cosine 学习率。

来源：options.py；server.py L170–171

训练批次

batch_size=14，nepoch=1（每轮通信本地 epoch 数）。每通信一次保存一个模型，无 early stopping。

来源：options.py；README.md

代码入口

  • 联邦训练：python server.py
  • 测试推理：python test.py（需配置测试集与保存路径）
  • 可视化：tensorboard --logdir=<save_path>
来源：README.md 使用文档

评估指标

README 记载本项目使用以下指标，并通过 TensorBoard 可视化全部评估结果：

  • RMSE — 源代码未更改；TensorBoard 中对应名称为 MSE。
  • MAE（相对误差）— 模型未拟合时可能出现 NaN/Inf；实现中剔除异常值并以 0 替换，会破坏 shape 与相对误差计算，前期 MAE 无参考价值。
  • PSNR — 源码提供计算函数，已纳入评估。
来源：README.md 评估指标章节

TensorBoard 命名（节选）

  • 服务端每轮均值：server_epoch_mean_MSE_evl、server_epoch_mean_MAE_evl、server_epoch_mean_PSNR_evl
  • 客户端验证：test_MSE_Loss、test_MAE_Loss、test_PSNR_Loss 等
来源：README.md TensorBoard 命名规则；server.py add_scalar 调用

已知限制与注意事项

以下内容均摘自 README.md 与源码注释，为仓库作者已披露的限制：

  • 运行环境：目前仅能通过编辑器 Remote 运行；nohup 启动服务端会报错且无法解决。
  • 硬件：客户端数量不能大于 GPU 数量；单卡加载多客户端时 batch size 受限，多卡并行逻辑难以解决。
  • 数据加载：num_workers > 0 会导致资源争抢死锁，程序不报错但 GPU 停止计算。
  • 客户端数量：数据分组已修复不均匀分配，但客户端过少（≤4）时不建议使用。
  • MAE 指标：训练前期因 NaN/Inf 处理策略，MAE 可能低于实际值，前期无参考价值。
  • 模型选择：无 early stopping，需人工对比通信次数选择最优模型。
  • 本 Pages 站点：纯静态 HTML，无法在浏览器中执行 PyTorch 训练或联邦通信；完整复现需在本地/服务器按 README 配置环境。
来源：README.md 结构介绍与使用文档；options.py

本地运行概要

  1. 安装依赖：pip install -r requirements.txt（PyTorch 1.7.1 等，见 requirements.txt）
  2. 在 options.py 配置数据路径、save_path、GPU 等参数
  3. 启动联邦训练：python server.py
  4. 查看日志：tensorboard --logdir=<save_path>，浏览器访问 ip:6006
  5. 测试：python test.py，运行前清空目标保存目录中的 .mat 文件
来源：README.md 使用文档；requirements.txt
